# RED Cleaner

트위터(X)의 **퍼블트 / 답글 / 리트윗**을 조건별로 골라 일괄 정리하는 확장 프로그램입니다.

---

## 설치

1. 크롬(또는 엣지·웨일)에서 `chrome://extensions` 접속
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** 클릭 → 이 폴더(`RED-Cleaner`) 선택
4. 이미 열려 있던 x.com 탭이 있다면 **새로고침** (콘텐츠 스크립트 주입 필요)

## 사용법

1. 내 프로필에서 아래 **두 곳을 각각 한 번씩** 연다.
   - **프로필 → 트윗 탭 → "전체"** (`https://x.com/내아이디/all`) — 퍼블트·리트윗이 여기 있습니다.
   - **프로필 → 답글 탭** (`https://x.com/내아이디/with_replies`) — 답글이 여기 있습니다.

   이 둘은 **서로 다른 API를 쓰는 별개 타임라인**입니다. 한쪽만 돌면 나머지가 그대로 남기 때문에, 정리도 두 타임라인을 각각 완주합니다. 각 페이지가 보내는 요청에서 세션 정보(authorization, queryId, features)를 잡습니다.

   팝업 배지가 **준비 완료(초록)** 면 두 곳 다 잡힌 상태이고, 팝업 위쪽에 잡힌 타임라인 경로가 표시됩니다. **일부 준비(노랑)** 면 한쪽만 잡힌 것이니 나머지도 한 번 열어주세요.
2. 확장 아이콘 클릭 → 조건 설정
3. 처음에는 **미리보기 모드**를 켜고 한 번 돌려서 로그로 대상 확인 (실제 삭제 안 함)
4. 확인되면 미리보기를 끄고 **정리 시작**

> 팝업을 닫아도 작업은 탭에서 계속 진행됩니다. **탭을 닫거나 새로고침하면 중단**됩니다.

## 기능

### 삭제 대상 필터 (중복 선택 가능)

| 대상 | 설명 |
| --- | --- |
| 퍼블트 | 답글도 리트윗도 아닌 내 단독 트윗 |
| 답글 | 다른 트윗에 단 답글 |
| 리트윗 | 내가 한 리트윗 (`DeleteRetweet` 으로 RT 취소) |

### 답글 세분화

- **멘션만 삭제** — 답글·퍼블트 중 *나 아닌 다른 계정을 멘션한 것*만 삭제합니다. 나 자신에게 단 답글이나 멘션 없는 트윗은 보존됩니다.
- **타래 유지** — `in_reply_to_user_id`가 나 자신인 답글(= 내가 이어쓴 타래)은 삭제하지 않습니다.

### 삭제 제외 조건

- **메인 트윗 제외** — 고정된 트윗 보존 (타임라인의 `TimelinePinEntry`로 판별)
- **미디어 제외** — 이미지·영상이 첨부된 트윗 보존
- **좋아요 기준 제외** — 설정한 좋아요 수 **이상**인 트윗 보존
- **내가 좋아요 누른 트윗 제외** — `favorited === true` 인 트윗 보존
- **리트윗 기준 제외** — 설정한 RT 수 **이상**인 트윗 보존
- **키워드 포함 제외** — 쉼표로 구분한 단어가 본문에 있으면 보존 (대소문자 무시, 긴 트윗의 `note_tweet` 본문도 검사)
- **지정 트윗 제외** — 트윗 ID 또는 링크를 쉼표로 구분해 입력. `https://x.com/계정/status/**1234**` 형태의 링크를 그대로 붙여넣어도 숫자만 추출합니다.
- **기간** — 특정 날짜 이후/이전만 대상으로 제한 (선택)

리트윗의 경우 미디어·좋아요·RT 수·키워드 판정은 **원본 트윗** 기준으로 합니다.

### 제한 회피 (스팸 방지)

- **배치 크기** — 기본 **300개**를 처리하면 자동으로 휴식
- **휴식 시간** — 기본 **5분**
- **삭제 간격** — 요청 사이 기본 700ms
- **총 삭제 상한** — 한 번 실행에서 지울 최대 개수 (비우면 무제한)
- `429`(요청 제한) 응답 시 3분 대기 후 자동 재시도, 개별 실패는 지수 백오프로 최대 5회 재시도

### 업데이트 확인

팝업 아래 **업데이트** 칸에서 GitHub 저장소를 지정해두면 새 버전이 나왔는지 확인합니다.

- 기본값은 `RED-Cleaner/beta` 이며, 입력란에서 `사용자명/저장소명` 형태로 바꿀 수 있습니다 (GitHub 주소를 그대로 붙여넣어도 됩니다).
- 확인 순서: **릴리스 → 태그 → 기본 브랜치의 `manifest.json` 버전**. 릴리스를 안 만들어도 `manifest.json`의 `version`만 올리면 감지됩니다.
- 6시간마다 자동 확인하고, 새 버전이 있으면 확장 아이콘에 **NEW 배지**가 붙고 팝업 상단에 배너가 뜹니다. **지금 확인** 버튼으로 즉시 확인할 수도 있습니다.
- 압축해제 확장은 브라우저가 자동 설치해 주지 않습니다. 배너의 **받기**로 릴리스 페이지에 가서 내려받고, 폴더를 교체한 뒤 `chrome://extensions` 에서 새로고침(↻)하면 됩니다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `manifest.json` | MV3 매니페스트 |
| `inject.js` | MAIN world에서 페이지의 `fetch` / `XMLHttpRequest`를 후킹해 실제 GraphQL 요청 URL·헤더를 확보 |
| `background.js` | `webRequest`로도 같은 정보를 관찰하고, 두 경로에서 모인 값을 `storage.session`에 보관 |
| `content.js` | 실제 엔진. 두 타임라인 순회 → 필터 판정 → `DeleteTweet` / `DeleteRetweet` 호출 |
| `update.js` | GitHub 릴리스/태그/manifest 버전을 비교해 새 버전 알림 (배지·배너) |
| `popup.html/js/css` | 설정 UI, 진행 상황·로그 표시 |

### 동작 원리

X 웹앱은 내부 GraphQL API를 쓰며, 엔드포인트마다 수시로 바뀌는 `queryId`와 `features` 파라미터를 요구합니다. 이 값을 하드코딩하면 금방 깨지므로, **브라우저가 실제로 보낸 요청 URL을 통째로 보관**해두고 `variables`(userId, cursor)만 바꿔 재사용합니다.

요청을 잡는 경로는 두 개입니다. X는 같은 GraphQL 호출을 `x.com/i/api/graphql/...` 로도, `api.x.com/graphql/...` 로도 보내기 때문에 `webRequest` 필터 하나에만 의존하면 놓칠 수 있습니다. 그래서 페이지 안에서 `fetch`/`XHR`을 직접 후킹하는 경로를 주 수단으로 두고, `webRequest`는 보조로 씁니다.

**트윗 탭의 "전체"(`/all`)와 답글 탭(`/with_replies`)은 별개 타임라인**이라 한쪽만 돌면 나머지가 남습니다. 선택한 대상에 따라 필요한 타임라인을 각각 완주하며, 이미 본 트윗 ID는 공유해 중복 처리하지 않습니다.

오퍼레이션 이름(`UserTweets` 등)은 X 가 언제든 바꿀 수 있어서 하드코딩하지 않았습니다. 대신 **요청이 어느 경로(`/all`, `/with_replies`)에서 나왔는지**를 같이 기록해 그 기준으로 타임라인을 구분합니다. 인증은 기존 로그인 쿠키(`ct0`, `auth_token`)를 그대로 씁니다 — 비밀번호나 API 키를 따로 입력할 필요가 없고, 외부로 나가는 데이터도 없습니다.

`DeleteTweet` / `DeleteRetweet`의 queryId는 X가 배포할 때마다 바뀝니다. 그래서 삭제를 시작하기 전에 **X 웹앱이 로드한 JS 번들(`abs.twimg.com/.../main.*.js`)에서 `{queryId, operationName}` 표를 직접 읽어** 최신 값을 확보합니다. 실행 중 `422 GRAPHQL_VALIDATION_FAILED`가 나면 그 자리에서 다시 읽어 갱신하고 재시도합니다.

우선순위는 **실제 요청 관찰 > 번들 추출 > 코드에 적힌 기본값** 순입니다.

## 주의

- **삭제된 트윗은 복구할 수 없습니다.** 먼저 미리보기 모드로 확인하세요.
- 필요하다면 X 설정에서 아카이브를 먼저 내려받아 두는 것을 권합니다.
- 대량 삭제는 X의 자동화 정책에 저촉될 수 있습니다. 배치·휴식 설정을 과하게 낮추지 마세요.
- 이 도구 사용으로 발생하는 계정 관련 문제는 사용자 본인 책임입니다.
