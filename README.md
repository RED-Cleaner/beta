# RED Cleaner

트위터(X)의 **게시물(퍼블트) · 답글 · 리트윗**을 조건별로 골라 정리하는 확장 프로그램입니다.

---

## 설치

1. 크롬(엣지·웨일)에서 `chrome://extensions` 을 엽니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드** → 이 폴더(`RED-Cleaner`)를 선택합니다.
4. 이미 열어둔 x.com 탭이 있으면 새로고침합니다.

## 사용법

1. 내 프로필에서 아래 다섯 곳을 **각각 한 번씩** 엽니다. (미디어-영상/미디어-사진 탭은 선택한 경우에만 필요)
   - **게시물 탭** (`x.com/내아이디`) — 내가 쓴 게시물이 있는 곳 ("@아이디"로 시작하는 글도 여기 있습니다)
   - **답글 탭** (`x.com/내아이디/with_replies`) — 답글이 있는 곳
   - **재게시 탭** (`x.com/내아이디/reposts`) — 내가 리트윗한 것이 있는 곳
   - **미디어-영상 탭** (`x.com/내아이디/media`) — 미디어 탭 기본 보기(영상 위주)
   - **미디어-사진 탭** (`x.com/내아이디/media?filter=photo`) — 미디어 탭에서 사진만 거른 보기

   각 탭은 서로 다른 목록이라, 하나만 열면 나머지는 지워지지 않습니다. 페이지를 열 때 확장이 필요한 정보를 자동으로 수집합니다.

   팝업의 배지가 **초록(준비 완료)** 이면 다섯 곳 다 잡힌 것이고, **노랑(일부 준비)** 이면 아직 다 못 잡은 것이니 나머지도 열어주세요.
2. 확장 아이콘을 눌러 조건을 설정합니다.
3. 먼저 **미리보기 모드**를 켜고 한 번 돌려서, 로그로 지워질 대상을 확인합니다. (실제로 지우지 않습니다)
4. 확인했으면 미리보기를 끄고 **삭제 시작**을 누릅니다.

> 팝업을 닫아도 작업은 계속됩니다. 다만 **탭을 닫거나 새로고침하면 멈춥니다.**

## 기능

### 지울 대상 (여러 개 선택 가능)

| 대상 | 설명 |
| --- | --- |
| 게시물 | 답글도 리트윗도 아닌 내가 쓴 트윗(퍼블트 삭제). "@아이디"로 시작하는 글도 포함됩니다. |
| 답글 | 다른 트윗에 단 답글 |
| 리트윗(재게시) | 내가 누른 리트윗 (리트윗 취소) |
| 미디어-영상 | 미디어 탭(`/media`)에 나오는 트윗/리트윗을 종류와 무관하게 모두 대상으로 삭제(또는 리트윗 취소)합니다. |
| 미디어-사진 | 미디어 탭의 사진 필터(`/media?filter=photo`)에 나오는 트윗/리트윗을 종류와 무관하게 모두 대상으로 삭제(또는 리트윗 취소)합니다. |

### 답글 관련 옵션

- **멘션만 삭제** — 진짜 답글이거나 "@아이디"로 시작하는 글 중, 다른 계정을 멘션한 것만 지웁니다. 문장 중간에 멘션이 섞인 평범한 게시물은 대상이 아닙니다.
- **타래 유지** — 내가 내 트윗에 이어 쓴 답글(타래)은 지우지 않습니다. 답글 기능 없이 그냥 "@내아이디"로 시작해서 쓴 글도 타래로 봅니다.

### 남겨둘 조건

- **고정 트윗 제외** — 프로필에 고정한 트윗은 남깁니다.
- **미디어 제외** — 사진·영상이 붙은 트윗은 남깁니다.
- **좋아요 기준 제외** — 좋아요가 정한 수 **이상**이면 남깁니다.
- **내가 좋아요 누른 트윗 제외**
- **리트윗 기준 제외** — 리트윗이 정한 수 **이상**이면 남깁니다.
- **키워드 제외** — 쉼표로 나눈 단어가 본문에 있으면 남깁니다. (대소문자 구분 안 함, 긴 글 본문도 검사)
- **지정 트윗 제외** — 트윗 링크나 ID를 쉼표로 나눠 입력합니다. 링크를 그대로 붙여넣어도 됩니다.
- **기간** — 특정 날짜 이후/이전만 대상으로 삼습니다. (선택)

리트윗은 미디어·좋아요·리트윗 수·키워드를 **원본 트윗** 기준으로 판단합니다.

### 제한 걸리지 않게

- **배치 크기** — 기본 **300개**를 처리하면 쉽니다.
- **휴식 시간** — 기본 **5분**
- **삭제 간격** — 기본 **700ms**
- **총 삭제 상한** — 한 번에 지울 최대 개수. 비워두면 무제한입니다.
- X가 요청 제한(`429`)을 걸면 기본 **3분** 기다렸다가 다시 시도하고, 하나가 실패하면 시간을 늘려가며 최대 5번까지 재시도합니다.

### 업데이트 확인

팝업 아래 **버전 확인** 칸에서 새 버전이 나왔는지 확인합니다.

- 확인할 저장소는 `RED-Cleaner/beta` 로 **고정**되어 있습니다.
- 확인 순서: **릴리스 → 태그 → 기본 브랜치의 `manifest.json` 버전**. 릴리스를 안 만들어도 `manifest.json` 의 `version` 만 올리면 잡힙니다.
- **24시간마다** 자동으로 확인합니다. 새 버전이 있으면 아이콘에 **NEW 배지**가 붙고 팝업 위에 배너가 뜹니다. **지금 확인** 버튼으로 바로 확인할 수도 있습니다.
- 압축해제 확장은 자동으로 업데이트되지 않습니다. 배너의 **받기**로 다운하거나, 저장소 열기를 통해 **CODE 초록색 버튼 → zip 파일 다운**하여 , 초기 설정과 같이 압축을 풀고 내용을 덮어씌운 뒤, `chrome://extensions` 에서 새로고침 혹은 다시로드 하세요.

## 구조

| 파일 | 역할 |
| --- | --- |
| `manifest.json` | 확장 설정 (MV3) |
| `inject.js` | 페이지의 `fetch` / `XMLHttpRequest` 를 가로채 실제 요청 주소와 헤더를 확보 |
| `background.js` | `webRequest` 로도 같은 정보를 관찰하고, 모은 값을 `storage.local` 에 보관 |
| `content.js` | 실제 동작. 게시물/답글/재게시 목록을 훑고 → 조건을 따져 → 삭제 요청을 보냄 |
| `update.js` | GitHub의 버전과 비교해 새 버전을 알림 (배지·배너) |
| `popup.html/js/css` | 설정 화면, 진행 상황과 로그 표시 |

### 어떻게 동작하나

X 웹앱은 내부 API를 쓰는데, 여기에 필요한 값(`queryId`, `features`)이 수시로 바뀝니다. 코드에 적어두면 금방 깨지므로, **브라우저가 실제로 보낸 요청 주소를 통째로 저장**해두고 트윗 위치 정보만 바꿔 다시 씁니다.

요청을 잡는 길은 두 개입니다. X는 같은 요청을 `x.com/i/api/graphql/...` 로도, `api.x.com/graphql/...` 로도 보내기 때문에 한 가지 방법만 쓰면 놓칠 수 있습니다. 그래서 페이지 안에서 직접 가로채는 쪽을 주로 쓰고, `webRequest` 는 보조로 씁니다.

**게시물 탭·답글 탭·재게시 탭·미디어-영상 탭·미디어-사진 탭은 서로 별개 목록**이라 하나만 훑으면 나머지가 남습니다. X 가 리트윗을 게시물 탭에서 분리해 별도의 재게시 탭(`/reposts`)으로 뺐기 때문에, 리트윗 삭제는 재게시 탭을 따로 훑어야 합니다. 그래서 선택한 대상에 맞는 목록을 각각 끝까지 훑되, 이미 본 트윗은 중복해서 건드리지 않습니다. 미디어 탭(영상/사진 모두)은 게시물/답글/리트윗 종류를 가리지 않고 그 탭에 나온 트윗을 전부 대상으로 봅니다.

API 이름(`UserTweets` 등)도 X가 언제든 바꿀 수 있어 적어두지 않았습니다. 대신 **그 요청이 어느 탭에서 나왔는지**를 같이 기록해 목록을 구분합니다. 로그인 정보는 이미 브라우저에 있는 쿠키를 그대로 씁니다 — 비밀번호나 API 키를 따로 넣을 필요가 없고, 밖으로 나가는 데이터도 없습니다.

삭제에 필요한 `queryId` 는 X가 배포할 때마다 바뀝니다. 그래서 시작 전에 **X가 불러온 JS 파일에서 최신 값을 직접 읽어옵니다.** 도중에 값이 낡아 오류가 나면 그 자리에서 다시 읽어 재시도합니다.

값을 정하는 우선순위는 **실제 요청에서 관찰한 값 → JS 파일에서 읽은 값 → 코드의 기본값** 순입니다.

## 주의

- **지운 트윗은 되살릴 수 없습니다.** 반드시 미리보기로 먼저 확인하세요.
- 걱정되면 X 설정에서 아카이브를 먼저 내려받아 두세요.
- 한꺼번에 많이 지우면 X의 자동화 정책에 걸릴 수 있습니다. 배치·휴식 값을 너무 낮추지 마세요.
- 이 도구를 써서 생긴 계정 문제는 사용자 본인 책임입니다.
